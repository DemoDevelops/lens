The control release: lens learns to stay out of your way. `lens off`/`lens on`, `lens status`, `lens clean`, central storage that keeps repos clean of `.lens` droppings, a scope guard that finally binds on the MCP server plane, and cold builds that no longer block the session. Measured against vanilla Claude Code on the frozen 34-task agentic benchmark (`claude-sonnet-5`, effort medium, tools live, 100% lens adoption): **+5.9pp accuracy (94% vs 88%), 48.6% fewer tokens, 51.7% faster time-to-answer** — up from v0.10's +4.9pp / -34.9% / -40.2% on the identical task set (see [BENCHMARKS.md](BENCHMARKS.md)). Covers everything merged since v0.10.1.

### Added

- **`lens off` / `lens on`.** A global denylist (`~/.lens/disabled`, one canonical path per line, subtree semantics) that every plane honors — hooks idle with a one-line note, the MCP server refuses auto-builds, `lens warmup` bails, federation skips the tree and says so. Nothing inside a disabled tree is ever touched.
- **Central storage.** Fresh indexes land at `~/.lens/projects/<hash>` instead of `<root>/.lens`, through one shared resolver every plane delegates to — hook, server, warmup, federation, dashboard can no longer disagree about where state lives. An existing in-tree `.lens` with a real index keeps being used where it is (keep-if-present: no index ever moves out from under a repo). `LENS_CENTRAL_STORE=0` restores the old layout.
- **`lens status [path]`.** One read-only screen: the scope verdict and why (marker, probe budget, disabled), the data dir and which rule chose it, index/graph freshness and on-disk size, a live builder's progress (pid-checked), and nested repos with per-repo build state. Guaranteed to create nothing — running it on a tree lens refuses to index leaves no droppings.
- **`lens clean [--all] [--yes]`.** Reclaims orphaned data dirs (roots that no longer exist, dirs nothing claims) plus stale probe files, driven by a new open-time registry (`~/.lens/registry.tsv`). Two guards in front of every deletion: nothing with a live build or fresh heartbeat is removed, and nothing that doesn't look like a lens data dir is ever a candidate — `bin/`, logs, and usage data are unreachable by construction.
- **RTK concierge.** lens no longer bundles or pins rtk (the pin had drifted 15 minor versions behind). Instead, `lens setup` and `lens update` detect your own install and — in an interactive terminal, always behind a y/N prompt — install the latest release, update an outdated rtk in place, migrate away the old bundled install, and register rtk's hook via `rtk init --global`. Scripted runs stay detect-only and never touch the network.

### Fixed

- **The scope guard now binds on the MCP server plane.** The server classifies a root *before* opening any store — previously the open itself planted `.lens`, which is a project marker, so the server indexed any directory it was pointed at (a 15k-file marker-less tree: hooks idled correctly, the server indexed all of it). Unscoped roots now redirect to `~/.lens/unscoped/<hash>` and every auto-build refuses with a clear message.
- **Closing the client stops the server in under a second.** A stdin watchdog ends the process ~0.8s after disconnect (previously it kept burning CPU — measured 219% for 6-10s — until in-flight work finished).
- **Tantivy merge-thread pileup on large trees.** Batched commits abandoned in-flight merges and stacked threads (measured 479 threads / 485% CPU on a real repo). The bulk path now waits for merges and caps the merge pool to the worker width.
- **Nested-repo federation is bounded.** The first search over a multi-repo workspace no longer auto-builds every nested repo unbounded: fresh builds are capped per call (`LENS_NESTED_AUTOBUILD_MAX_REPOS`, default 8), each build lands centrally, and every skip is named in the response notes.
- **`lens warmup <path>` wrote to the wrong place.** It resolved its data dir from the *cwd*, not the path argument; it now builds exactly where the server for that path will read.

### Improved

- **Cold large repos answer immediately.** The first build of a 1000+-file repo detaches at OS background priority with both thread pools capped (`nice` 19 + Darwin background QoS; measured 94-167% CPU on a Go monorepo, down from saturating the machine). The first call returns in 0.02-0.16s with partial results and a one-line note instead of blocking 9-12s; graph queries refuse with a retry message until the graph exists. The builder leashes itself to live sessions and exits within seconds of the last one disconnecting. `LENS_BACKGROUND_BUILD=0` restores blocking builds.
- **Every new behavior has a kill switch, default-ON:** `LENS_SCOPE_GUARD=0`, `LENS_BACKGROUND_BUILD=0`, `LENS_CENTRAL_STORE=0`, `LENS_NESTED_AUTOBUILD=0`. The README's new **Controls** section documents the full set.
